# P1.4 — NORM-CS-001 cross-system normalisation

| Field | Value |
| --- | --- |
| Contract | `NORM-CS-001` |
| Version | `seqlogad-normalizer-cs-v1` |
| Rule file | `configs/parsing/normalizer-cs-v1.yaml` |
| Implementation | `src/seqlogad/protocol/normalizer.py` |
| Tests | `tests/protocol/test_normalizer.py`, `tests/protocol/test_nul_codec.py` |

Excel definition of done: *"Raw semantic text không bị mất; transform deterministic."*

## Layers

```text
exact raw line bytes
  └─ adapter: separate metadata and any inline ground-truth marker
       └─ raw_message_bytes            ── hashed as raw_message_sha256
            └─ seqlogad-nul-escape-v1  ── canonical_message (NUL-free, reversible)
                 └─ NORM-CS-001        ── normalized_message (masked)
```

`raw_message_bytes` is never mutated. `canonical_message` is recoverable from
`normalized_message`? No — masking is lossy by design, which is why the canonical
layer and its hash exist: the raw text stays provable through
`raw_message_sha256`, and the canonical text is reproducible from the raw bytes by
re-running a versioned, deterministic transform.

## Rules

The rule table is data, not code, so the exact masking behaviour is reviewable and
hashable. Its SHA-256 is bound into every stream index, fold manifest, buffer
manifest and the G0 receipt; changing one byte invalidates all of them.

17 masking rules run in a fixed order: `UUID`, ISO timestamp, clock time, IPv6,
IPv4+port, IPv4, MAC, HDFS block id, YARN identifier, BGL node location, BGL node,
URL, email, long hex, control character, number, residual number. Five `preserve`
patterns are protected before masking and restored afterwards, so business-meaningful
tokens survive the numeric rule.

Worked examples (these are the test's golden cases, not illustrations):

| Raw | Normalised |
| --- | --- |
| `Receiving block blk_-1608999687919862906 src: /10.251.31.5:56682 dest: /10.251.31.5:50010` | `Receiving block <BLK> src: /<IP>:<PORT> dest: /<IP>:<PORT>` |
| `2015-10-17 21:47:48,288 INFO Created MRAppMaster for application appattempt_1445087491445_0005_000001` | `<TS> INFO Created MRAppMaster for application <YARNID>` |
| `instance 544fd51c-4edc-4780-baae-ba1d80a0acfc spawned` | `instance <UUID> spawned` |
| `ciod: LOGIN chdir(/p/gb1/stella/RAPTOR) failed on R02-M1-N0-C:J12-U11` | `ciod: LOGIN chdir(/p/gb1/stella/RAPTOR) failed on <NODE>` |
| `checksum deadbeefcafe1234 over IPv4 TCP on x86_64 using SHA-256` | `checksum <HEX> over IPv4 TCP on x86_64 using SHA-256` |
| `"GET /v2/servers/detail HTTP/1.1" status: 200 len: 1893` | `"GET /v2/servers/detail HTTP/1.1" status: <NUM> len: <NUM>` |

The last two rows are the point of the `preserve` list. Without it, `HTTP/1.1`,
`SHA-256`, `IPv4` and `x86_64` all collapse to `<NUM>`, and the message stops saying
what protocol or architecture it was about. Two defects found and fixed while
building the golden cases:

1. Preservation placeholders originally embedded a decimal index, which the numeric
   rule then masked, destroying every preserved token. Placeholders are now built
   purely from private-use code points that no rule can match.
2. `residual_number` used `(?<![A-Za-z_])\d+(?![A-Za-z_])`, which backtracked into
   `54fadb` and rewrote it as `<NUM>4fadb`. The lookarounds are now `\w`-based.

## Measured effect

| Architecture | Records | Distinct raw messages | Distinct normalised | Reduction |
| --- | ---: | ---: | ---: | ---: |
| `ARCH-HDFS` | 11,175,629 | 10,335,015 | 34,324 | 99.67% |
| `ARCH-BGL` | 4,747,963 | 358,357 | 20,338 | 94.32% |
| `ARCH-HADOOP` | 394,310 | 62,468 | 25,812 | 58.68% |
| `ARCH-OPENSTACK` | 207,820 | 151,409 | 4,605 | 96.96% |

Hadoop's 58.68% is the outlier and is explained by its `CONTINUATION` records: a
stack-trace frame is mostly class and method names, which masking barely touches.

## Properties enforced

- **Deterministic** — the rule table has no fitted state; running the transform twice
  gives identical output, asserted per golden case.
- **Versioned** — `seqlogad-normalizer-cs-v1`, with the rule-file digest bound into
  every artifact.
- **Not label-dependent, not partition-dependent, not architecture-dependent** — the
  rule file must declare all three as `false` or the loader refuses it, and a test
  builds a tampered rule file to prove the refusal.
- **Non-destructive** — `raw_message` is untouched; a test asserts the input string
  is unchanged after normalisation.
- **No silent drops** — control characters become `<CTRL>` rather than disappearing;
  `0x00` is handled one layer earlier by the reversible NUL codec.

## Relationship to Drain3

Excel P1.4 says the Drain3 template *"chỉ là trường phụ trợ"* — an auxiliary field.
No template is fitted or populated in Phase 1, and `CanonicalLogRecord.template_id`
stays null. Populating it later requires a declared `template_source`, and no parser
may be fitted on a target evaluation partition.
