# P2.2 — Sequence-LoRA Reference Development Contract

Contract: **LORA-SEQ-001 v1.0** · authority: user-approved autonomous P2.2
implementation on **2026-09-19**. Machine companion:
[`configs/models/sequence-reference-v1.yaml`](../../configs/models/sequence-reference-v1.yaml).

Status at freeze: **development implementation authorized for seed 42**. This

or establish anomaly-detection performance.

## Objective and isolation

P2.2 adapts the same immutable Llama-3.1-8B revision used by P2.1 with a separate
`sequence` LoRA adapter. It predicts the next normalized log message from ordered
predecessor messages. Loss and validation use only next-message target tokens.
The Semantic adapter, its checkpoints, optimizer and RNG state are forbidden
inputs.

Only `SOURCE_TRAIN` fits parameters. `SOURCE_VALIDATION` performs label-free
checkpoint selection. Target partitions, anomaly labels, label-derived filtering,
source `LATE`, guards and excluded records are forbidden.

## Ordered context and reset policy

- A window contains one target record and up to eight immediately preceding
  records from the same architecture, partition and group/session.
- Where Phase-1 has a non-negative group identity, it is mandatory. Records with
  no group use one explicitly declared architecture-partition chronology.
- Context never crosses architecture, train/validation, guard, excluded or target
  boundaries. Repetition is preserved and there is no implicit deduplication.
- The portable builder materializes a deterministic, label-free candidate pool:
  32,768 train and 2,048 validation windows per available source, selected by a
  stable hash of architecture, partition and target rank. Smaller eligible pools
  are retained completely.
- The tokenizer context is 512 tokens. If necessary, encoding drops the oldest
  whole predecessor record first, then decreases only the retained prefix of the
  target message. Coverage and retained record/rank identities are emitted. At
  least one predecessor and one target word are required.
- EOS is appended only when the complete target message is retained. Existing
  tokenizer tokens are used; vocabulary and embeddings are never resized.

## Development budget

The seed-42 RunPod wave uses equal-size source sampling with replacement: 8,192
training windows and 512 validation windows per source, effective batch 16,
maximum 1,536 optimizer steps, learning rate `1e-4`, warmup 100, validation and
checkpoint every 100 steps, and early stopping after three validations without
an improvement of at least `0.001` aggregate next-log NLL. Ties select the
earliest checkpoint. LoRA is rank 16, alpha 32, dropout 0.05 on q/k/v/o
projections. This mirrors the P2.1 development resource class for comparability;
it is not a measured equality of compute.

## Evidence and controls

Each run must retain aggregate/per-source next-log NLL, coverage/rejections,
selected checkpoint, runtime/VRAM, environment, input/config identities and six
isolated sequence controls: permutation, missing event, duplicate event,
unexpected next event, long-range dependency violation and locally plausible but
globally invalid ordering. Control truth is diagnostic metadata only and cannot
select a winner or stand in for natural anomaly performance.

Every checkpoint is adapter-only, hash sealed and resumable with optimizer,
scaler, RNG, scheduler and early-stopping state. Completed targets and recovery
snapshots are published atomically to the RunPod Network Volume. A final ZIP is
safe to stop only after its checksum sidecar and nested ledgers verify.

## Definition of done

Local completion requires a validated portable sequence bundle, authoritative
trainer and standalone scorer, sequence-control tests, clean one-click RunPod A40
notebook, deterministic upload kit and passing focused regression tests. Live GPU
completion remains `NOT_STARTED` until the researcher runs the notebook and
returns its artifacts for review.
