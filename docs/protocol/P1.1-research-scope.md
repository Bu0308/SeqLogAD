## 1. What counts as an architecture

An **architecture** is a distinct log-producing system or domain: a different
software stack emitting logs with its own vocabulary, field layout, component
namespace and failure semantics.

An architecture is **not**:

- a subset, shard or time slice of one dataset;
- a grouping by EventID or template;
- a random partition of a mixed corpus.

The active architectures and the domain each represents:

| Architecture | System | Domain |
| --- | --- | --- |
| `ARCH-HDFS` | Hadoop Distributed File System v1 | distributed storage daemons |
| `ARCH-BGL` | IBM Blue Gene/L | HPC supercomputer RAS/syslog |
| `ARCH-HADOOP` | Hadoop YARN / MapReduce containers | batch compute framework |
| `ARCH-OPENSTACK` | OpenStack Nova services | cloud IaaS control plane |

These are four different stacks with four different log grammars, not four views of
one system. `ARCH-HDFS` and `ARCH-HADOOP` share an ecosystem but not a log producer:
one is filesystem daemon output (`dfs.DataNode`, block lifecycle), the other is
application/container output (`org.apache.hadoop.mapreduce`, task attempts). Their
field layouts, component namespaces and message vocabularies are disjoint.

## 2. Unseen target

Within a fold, exactly one architecture is the **target** and is held out. It never
appears in that fold's source training or source validation partition. "Unseen"
means unseen *by that fold's model*, which is the only sense in which this project
may use the word.

`ARCH-OPENSTACK` is an **active source architecture that is not target-eligible**.
Its raw data ships as three separate capture sessions. The only label-blind way to
order those sessions is wall clock, and wall clock puts the entire anomaly-bearing
capture (2017-05-14) strictly before both normal captures (2017-05-16/17). A
label-blind chronological burn-in would then swallow every anomaly and leave an
evaluation window with no positives. Ordering the sessions any other way means using
the source-provided normal/abnormal file identity, which is ground truth. Rather
than launder a label into the split, the architecture is used as a source only, and
the exclusion is recorded here and in the registry.

This yields three LOAO folds, each with three source architectures — which meets the
Excel G0 requirement of at least three source architectures.

## 3. One fold, end to end

```text
                 ┌──────────────────── SOURCES (3 architectures) ───────────────────┐
                 │  EARLY segment  ───────────────►  SOURCE_TRAIN                    │
                 │  GUARD segment  ───────────────►  (unused)                        │
                 │  MID   segment  ───────────────►  SOURCE_VALIDATION               │
                 └──────────────────────────────────────────────────────────────────┘
                                              │
                                              │  representation + experts (P2)
                                              ▼
                 ┌──────────────────── TARGET (1 held-out architecture) ────────────┐
   time ───────► │  EARLY segment  ───────────────►  TARGET_BURN_IN   (no labels)    │
                 │  GUARD segment  ───────────────►  (unused)                        │
                 │  MID + LATE     ───────────────►  TARGET_EVALUATION (labels here  │
                 │                                    and nowhere else)              │
                 └──────────────────────────────────────────────────────────────────┘
```

Every boundary is a time boundary. `TARGET_BURN_IN` strictly precedes
`TARGET_EVALUATION`; `SOURCE_TRAIN` strictly precedes `SOURCE_VALIDATION`. Both are
verified per fold by check `L07` of the isolation audit, not asserted.

## 4. Fields forbidden at each step

| Step | May read | May **not** read |
| --- | --- | --- |
| Canonicalisation (NUL codec) | raw message bytes | label, partition, fold role, parent, model result |
| Normalisation (`NORM-CS-001`) | canonical message text | label, partition, fold role, architecture role, model result |
| Chronological indexing | timestamps, file order, grouping key | any label |
| Fold construction (`CS-SPLIT-001`) | chronology, grouping-unit lifetimes | any label; source-provided normal/abnormal file identity |
| Target buffer (`ADAPT-INPUT-001`) | chronology only | any target label; any normal/abnormal marker |
| Representation / expert training (P2) | source partitions | **target labels** |
| Target adaptation, calibration, drift, gate (P3) | target burn-in buffer, source episodes | **target labels** |
| Final evaluation (P4) | target labels | — |

The prohibition is explicitly on the operation

```text
select records where label == normal
```

as a way of constructing an adaptation buffer. The buffer is a chronological prefix
and nothing else. "Normal burn-in" is therefore an **operational assumption** with a
declared contamination bound, not a fact established from ground truth.

## 5. How the prohibition is enforced

Documentation alone would not be enforcement. Three mechanisms back it:

1. **The record has no label field.** `CanonicalLogRecord` (LOG-UNIFY-001) rejects
   any field whose name looks like supervision, so there is nothing to leak through
   the adaptation-facing object.
2. **The adapters strip inline ground truth.** BGL carries its alert marker in
   column 0; the adapter drops it before the record exists.
3. **The label boundary is a separate module with a scope check.**
   `seqlogad.protocol.labels` refuses every scope in a forbidden list, records each
   access, and is imported by no module on the adaptation path. Audit check `L09`
   re-derives this from the import graph on every run, and a test asserts it.

## 6. Claim boundary

Claims are limited to the architectures and operating conditions actually evaluated.
Universal cross-system generalisation is not claimed, and cold-start detection
before a sufficient burn-in buffer is not claimed. No empirical result exists yet.
