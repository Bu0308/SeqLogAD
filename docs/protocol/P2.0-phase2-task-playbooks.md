# P2.0 — Mandatory future task playbooks

Normative appendix to [P2-ARCH-001](P2.0-phase2-architecture-contract.md).
IDs use P2_ARCH_V1 after P2.0.1 migration. P2.1–P2.7 NOT_STARTED; P2.PRE metadata freeze PASS; P2.1 execution-authorized, not started.
P2.PRE metadata work comes first; see [its definition](../../configs/models/base-freeze-v1.yaml).
Its DoD is reviewed immutable metadata, not a model download. P2.1 remains blocked.
Execution order is P2.PRE → P2.1 → P2.2 → P2.3 → P2.4 → P2.5 → P2.6 → P2.7.

### P2.1 — Semantic Expert

- **Objective:** independent semantic expert, retained canonical-text semantics.
- **Repository inputs:** G0 receipt, schema.py, frozen normalizer/split/folds,
  model stub, P2.0 evidence envelope; P2.PRE base-freeze metadata.
- **Data / allowed:** SOURCE_TRAIN fitting; SOURCE_VALIDATION label-free selection.
- **Forbidden:** all anomaly labels, all target data, validation fitting; shared adapter state.
- **Objective to train:** masked/reconstruction-style semantic self-supervision;
  specify causal-Llama-compatible formulation before run; not bidirectional MLM by assertion.
- **Outputs/artifacts:** LLM-BASE-001, LORA-SEM-001, EXP-SEM-001;
  semantic prepared view, pinned base/tokenizer/license/budget, notebook and run bundle.
- **Evaluation/tests:** semantic perturbation and format/OOV controls, label stripping,
  deterministic identity, data boundaries, score direction, notebook smoke/resume.
- **DoD:** standalone inference + evidence, verified data/run manifests, declared
  limitations, bounded source validation; no claimed target performance.
- **Dependencies:** P2.PRE PASS and explicit execution authorization; base smoke-load before training.
- **Risks:** contaminated source population, normalization loss, token budget;
  source contrastive pairs/DANN must be declared and evaluated separately.

### P2.2 — Sequence Reference Framework

- **Objective:** common ordered-context framework and reference Sequence-LoRA.
- **Repository inputs:** P2.PRE frozen base and P2.1 lineage, P1 schema/folds, P2.0 controls.
- **Data / allowed:** source train/validation only, same partitions as P2.1.
- **Forbidden:** target data/labels, label-based windows, boundary crossing, implicit deduplication.
- **Objective to train:** causal next-event/next-log likelihood with fixed scoring unit.
- **Outputs/artifacts:** shared sequence view, context/vocabulary config, LORA-SEQ-001,
  EXP-SEQ-001, reference notebook, independent checkpoint and run manifest.
- **Evaluation/tests:** all six sequence controls; context identity, causality,
  multiplicity, session/end/reset, missing time, OOV and truncation tests.
- **DoD:** independently usable reference; reproducible sequence construction;
  observed capability limits recorded; no winner claim.
- **Dependencies:** P2.1 base/input contract; never requires copying semantic adapter.
- **Risks:** context length, tokenization of EventIDs, absent end semantics, expensive passes.

### P2.3 — Lightweight Sequence Expert

- **Objective:** test whether a substantially cheaper explicit sequence model preserves capability.
- **Repository inputs:** P2.2 shared contexts/evaluation interface and frozen budget.
- **Data / allowed:** identical source memberships and information access to reference.
- **Forbidden:** target data/labels, extra future context, comparator-specific label filtering.
- **Objective to train:** explicit causal sequential objective; GRU/small causal
  Transformer family choice and loss must be frozen before training.
- **Outputs/artifacts:** EXP-SEQ-LIGHT-001, model config/checkpoints, notebook/run bundle;
  shared sequence view, no independent competing sequence materializer.
- **Evaluation/tests:** same six controls, source objective, params/tokens/time/VRAM/latency;
  verify information/budget differences disclosed and boundary tests reused.
- **DoD:** at least one runnable substantially lighter candidate measured against
  reference; predeclared resource criterion met or failure reported, not hidden.
- **Dependencies:** P2.2; numeric resource criterion must be preregistered before run.
- **Risks:** short context or lossy embeddings masquerading as a fair cheap replacement.

### P2.4 — GTAT Expert

- **Objective:** independently usable structural-temporal relation expert.
- **Repository inputs:** P1 field coverage/folds, P2.1 semantic view if used, section 4 spec.
- **Data / allowed:** source train fitting, separate source validation graph construction.
- **Forbidden:** target data/labels, invented topology, unrecorded sequence-role substitution.
- **Objective to train:** explicit structural-temporal self-supervised loss, currently
  unresolved; a clean-normal-only objective cannot assume clean source membership.
- **Outputs/artifacts:** EXP-GTAT-001, graph view/schema/config, coverage/evidence,
  model checkpoint, notebook and run bundle with source/model attribution.
- **Evaluation/tests:** edge/node/time definitions, collisions, order controls,
  absent metadata, coverage/abstain, session boundaries and inductive OOV behavior.
- **DoD:** every section 4 item fixed; standalone scoring and honest temporal limits;
  no claim GTAT replaces explicit sequence modeling.
- **Dependencies:** P2.3 complete (execution order); P2.1 representation contract as input; GTAT specification resolution before train.
- **Risks:** graph aggregation loses order; poor topology coverage; source-specific IDs.

### P2.5 — Common Evidence Contract

- **Objective:** implement strict shared evidence API for all four candidate IDs.
- **Repository inputs:** P2.0 envelope and P2.1–P2.4 expert outputs.
- **Data / allowed:** label-free synthetic fixtures and source validation predictions.
- **Forbidden:** labels joined into model input, fake calibrated scores or confidence.
- **Training objective:** none; this task is schema/adapter validation, not a model.
- **Outputs/artifacts:** EVID-CS-001 versioned schema, converters, valid/invalid samples.
- **Evaluation/tests:** unique identity, finite scores/ranges, missing-field rejection,
  provenance, localisation bounds, explicit null/unavailable states and abstention.
- **DoD:** every candidate validates; one expert can be consumed alone; no P3 activation.
- **Dependencies:** P2.4 complete, transitively P2.1–P2.3; minimum envelope frozen here guides earlier implementation.
- **Risks:** schema conflates uncertainty/coverage or forces nonexistent calibration.

### P2.6 — Expert Diversity / Scientific Evaluation

- **Objective:** quantify differences and incremental capability; prepare G2 evidence.
- **Repository inputs:** EVID-CS-001, frozen candidate configurations, selection protocol.
- **Data / allowed:** source-held-out predictions and isolated synthetic control metadata.
- **Forbidden:** outer-target evaluation or labels; reuse of P4 scope for source selection.
- **Training objective:** none; any retraining delegates to its owning P2.1–P2.4 module/notebook.
- **Outputs/artifacts:** DIV-P2-001, paired predictions/control scores, resource report,
  selection policy and unresolved-label-scope report; preserve null/negative findings.
- **Evaluation/tests:** compare reference/lightweight/GTAT and semantic residual cases;
  independent vs correlated errors only where legal truth exists; paired unit/seed integrity.
- **DoD:** auditable diversity evidence with uncertainty; real AP/FAR/double-fault
  blocked by C2 until authorized. Synthetic success alone cannot close scientific DoD.
- **Dependencies:** P2.5; C2 for supervised source evidence; no gate fitting.
- **Risks:** label-granularity mismatch, low statistical power, post-hoc threshold/margin.

### P2.7 — Final Phase-2 Freeze

- **Objective:** freeze reproducible expert package for later Phase 3 consumption.
- **Repository inputs:** all P2 artifacts, hashes, test evidence, unresolved issues.
- **Data / allowed:** manifests and source-derived outputs; no fresh target access.
- **Forbidden:** training, selecting winner without evidence, passing G2 as an agent.
- **Training objective:** none.
- **Outputs/artifacts:** P2-FREEZE-001, candidate disposition, artifact hashes,
  inference entry points, notebook inventory, limitations and researcher review packet.
- **Evaluation/tests:** reproducibility from relocated bundle, schema compatibility,
  required artifacts/versions, legal access, no orphan predictions or incomplete runs.
- **DoD:** all prerequisite DoDs satisfied or explicitly blocked; researcher reviews
  G2 separately; no automatic launch of P3.
- **Dependencies:** P2.6; unresolved material capability/label/routing issues block closure.
- **Risks:** treating code completion as scientific evidence or a gate signature.
