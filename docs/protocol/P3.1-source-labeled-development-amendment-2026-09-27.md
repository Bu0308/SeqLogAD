The researcher clarified that public anomaly labels supplied with the Loghub
datasets may form a **labeled source development set** for Sequence Expert
checkpoint selection. This supersedes the earlier statement that no labeled
development set is available. It does not retroactively change the frozen V11
or V12 NLL runs and kits. A new version must carry the changed validation
policy in its config, run ID, data manifest, checkpoint identity and Projmem
variant record before training.

## Per-fold access boundary

For a fold holding out architecture T, construct development examples only
from that fold's `SOURCE_VALIDATION` windows of architectures other than T.
Ground truth may annotate these source validation examples for checkpoint
selection and threshold development. `SOURCE_TRAIN` continues to fit the
next-log model without anomaly labels. T's labels and `TARGET_EVALUATION`
remain unavailable to that fold's training/selection path until locked final
evaluation. No labels may choose
target burn-in, calibration, adaptation or fusion behavior.

This is a change from `SOURCE_ONLY_LABEL_FREE` to **label-free source training
with labeled source development**. It must be named in reports; public labels
are not a substitute for a held-out target result.

| BGL | First-column alert marker (`-` means non-alert) | Target log line |

| Hadoop | `abnormal_label.txt` | Application; aggregate scores of its selected target log lines |

The local registry identifies all three sources, and the three corresponding
raw/label files were found on 2026-09-27. Unit-to-window joins must be checked
against the immutable Phase-1 chronological rank and fold membership, with
complete join coverage and source-role verification. Store only source
development labels needed by a fold in a separately hashed sidecar; never put
them into model prompts, feature tensors, or the label-free sequence view.

The current 2,048-window candidate pool covers only five Hadoop applications
in each fold where Hadoop is a source. BGL's global `sequence_id` is not a
log-line evaluation unit. OpenStack validation lies after the abnormal capture
in the frozen chronology, so it should not be assumed to offer both classes.
Validate class counts and independent-unit coverage before including either
Hadoop or OpenStack in a source F1 aggregate. A missing class must fail closed,
not silently yield an F1 or switch to another stopping rule.

## Metrics and selection to freeze before execution

Compute high-NLL anomaly scores on full-context source validation windows.
Specify the per-unit aggregation and threshold search **before** looking at
the labels' score relationship. At each checkpoint calculate source
development precision, recall, F1, accuracy, AUROC and non-interpolated
average precision (AP), with positive-class counts and coverage. Select and
early-stop by predeclared source-development F1, ties choosing the earlier
checkpoint. Report the selected threshold and the selection optimism caused
by using the same development set for threshold and checkpoint selection.
AUROC and AP do not require a classification threshold; precision, recall,
F1 and accuracy do. A source development result is not a target test result.

Only after the model, score aggregation, threshold/calibration policy and
evaluation unit are frozen may the final target labels be opened once to
calculate target accuracy, precision, recall, F1, AUROC and AP. Published paper
numbers may be shown as contextual baselines only when dataset version,
split, scoring unit and metric definition are stated; otherwise label them
non-equivalent protocols.

## V13R1 audit clarification — 2026-10-03

The frozen V13 development cohort has 512 BGL lines (16 positive) and
512 HDFS windows spanning 511 blocks (10 positive). HDFS block scores average
only selected windows, not the complete trace. Source F1 maximizes a threshold
on the same cohort used for checkpoint selection and is a tuning metric.
It does not prescribe the future unseen-target threshold or estimate test F1.
Early stopping retains patience 3; small positive counts can make it noisy.

The original builder parsed the complete public HDFS label CSV before keeping
source-validation entries. Its `target_labels_read: false` metadata was too
strong. R1 records this historical access honestly and asserts only that
held-out target labels are not used for selection in a fold. The R1 sidecar
is migrated from existing per-fold entries without reopening raw labels.
Future builds convert label values only for authorized source block IDs;
scanning a CSV still physically reads bytes outside the selected rows.

R1 requires exact selected-label score coverage, identical evaluation precision,
and terminal-checkpoint finalization without extra updates. Its separate run
IDs, persistence root and code digest prevent reuse of old execution state.
The eight-record/512-token receptive field is bounded. Natural-log sequence
ablations and same-protocol baselines remain required before performance claims.
