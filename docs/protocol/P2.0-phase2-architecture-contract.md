## 3. Sequence capability and lightweight hypothesis

**SEQLOGAD-SPECIFIC PROTOCOL DECISION:** keep explicit sequence capability;
compare the reference against at least one substantially lighter sequence model.
Do not remove/replace Sequence-LoRA, select a winner, or assume GTAT replaces it.

The later evaluation must include: event permutation, missing event, duplicate
event, unexpected next event, long-range dependency violation, and locally
plausible but globally invalid sequence. Include intact controls, no-op controls,
same-multiset reorder cases, and length/multiplicity-matched controls where valid.
Synthetic anomaly truth is isolated evaluator metadata, not a training column.
It is not natural ground truth and cannot by itself justify deployment or G2.

Builders must preserve ordered occurrences, repetition, typed actual/effective
time, stable tie-breaking and session/group IDs. Never join across architecture,
fold, partition, excluded records or guard boundaries. Declare truncation, stride,
maximum context, session-end/timeout semantics and reset policy before training.
A missing event is observable only relative to an expected continuation/completion;
a long-range claim applies only within the tested effective context horizon.

Graph counterexample: ABACA and ACABA have identical event counts and directed
transition counts. An event-type transition-count graph without occurrence order
cannot distinguish them. Calibration/fusion cannot reconstruct discarded input.
This is a representation argument, not a claim that every graph model fails.

## 4. GTAT resolution prerequisite

GTAT is currently a planned family, not a runnable or fully sourced model. Before
P2.4 training, freeze all of the following in its model/config manifest:

- Exact paper/model identity, reproducible revision, and which modifications are
  SeqLogAD decisions; resolve RSG-001 rather than attaching a vague citation.
- Node identity: event type versus occurrence, optional service/component nodes;
  raw-parameter and semantic features, OOV and missing-field policies.
- Directed/undirected edge types, weights, multiplicity/self-loops, temporal versus
  co-occurrence relation, construction window/session and boundary policy.
- Position/delta-time encoding, timestamp masks, causal receptive field, long-range
  horizon and tests for order collisions. Do not invent causal edges from adjacency.
- Loss, allowed fitting population, score formula/direction, aggregation and
  evidence mapping; normal-only compatibility must match available data.
- Coverage denominator, abstention criteria and portability across unseen systems.
  Low graph coverage must not silently remove explicit sequence capability.

Logs2Graphs and LogGT inform this design, but neither identifies the project's
exact GTAT implementation or proves substitutability [L1, L7].

SOURCE_TRAIN = EARLY; SOURCE_VALIDATION = MID; TARGET_BURN_IN = EARLY of the
held-out architecture; TARGET_EVALUATION = MID+LATE of that architecture. GUARD
is unused. Membership is copied from frozen fold artifacts, never recomputed by
random splitting on the GPU host. Outer target architecture never enters source
training/validation of that fold. Inner source-held-out selection must refit all
learned preprocessing on inner training sources and exclude the inner held-out
architecture from fitting; freeze its episode manifest before the pilot.

Source partitions are **not established clean normal data**. Self-supervision is
label-free learning on the authorized population, not proof of normal-only training.
A method requiring verified normal source examples is blocked until a compatible
population/label-access decision exists. Do not silently filter by labels or scores.

P2 trainers cannot read TARGET_BURN_IN even without labels; target-local work is
Phase 3. Its buffer remains a label-blind chronological prefix, with assumed 5%
contamination bound, not a measured normal set. Hadoop buffer rejection still blocks
its target adaptation; P2.0 neither relaxes readiness nor regenerates any fold.

## 7. Canonical portable training-data layout

**Canonical root: `data/phase2/` — NOT CREATED YET.** This is a future data product,
not a relocation of `data/raw/` or a replacement for P1's `data/processed/protocol/`.
Existing compact stream indices are insufficient for model training by themselves.

```text
data/phase2/
  README.md
  manifests/{bundle.json,checksums.sha256}
  folds/<fold_id>/
    manifests/{fold.json,lineage.json}
    metadata/normalizer-cs-v1.yaml
    semantic/{train/records.parquet,val/records.parquet,metadata/view.json}
    sequence/{train/windows.parquet,val/windows.parquet,
              metadata/events.parquet,metadata/view.json}
    graph/{train/graphs.parquet,val/graphs.parquet,
           metadata/nodes.parquet,metadata/view.json}
```

- P2.1 owns common materialization/manifest helpers and creates semantic data.
  Reconstruct label-stripped canonical records from permitted raw membership,
  verify raw/normalized hashes and source rank; never join using `gid` alone.
- P2.2 creates sequence data and reference/event metadata. P2.3 reads the same
  view; it must not create a second independent source-of-truth sequence corpus.
- P2.4 creates graph data from declared permitted records and graph specification.
- `train` is SOURCE_TRAIN; `val` is SOURCE_VALIDATION. A `reference` is derived
  only from SOURCE_TRAIN and stored under metadata/run artifacts with fitting
  membership hashes. There is no secretly label-filtered reference partition.
- Semantic records must contain the required LOG-UNIFY-001 fields and stable
  record IDs; sequence rows contain ordered record/event IDs, positions, times,
  masks and context boundaries. Referenced text/features are in events.parquet.
  Graph rows contain graph IDs, node IDs, typed edges/weights/time attributes;
  all referenced features are in nodes.parquet. Every view defines its versioned
  physical schema in metadata/view.json before materialization.
- Optional semantic token cache and sequence/graph embedding caches may be
  omitted; they must be reproducible from included data and pinned model assets.
  If referenced as necessary inputs, they become required manifest entries.
- No per-unit labels, aggregate label inventories, normal/abnormal filenames,
  label sidecars or target content are packaged. Opaque source-file IDs may replace
  label-bearing provenance paths; private reverse lineage stays outside upload.
  The GPU trainer never needs to discover or read original raw-data locations.
- Each bundle manifests only views already prepared and required by its selected
  expert. Semantic training does not require later graph preparation. The full
  prepared bundle eventually includes all views. Missing required entries fail closed.

Every manifest file entry records dataset and architecture identity, fold and exact
partition, record and sample counts (windows/graphs differ from records), schema
version, relative path, SHA-256, membership digest, source-corpus and stream-index
hashes, P1 receipt/split/normalizer hashes, builder revision/config hash and provenance.
Record `target_labels_read: false`, `label_columns: []`, and `label_policy` explicitly.
`fold.json` binds copied frozen membership, target/source roles and boundary policy;
`lineage.json` binds source artifacts without exposing label-bearing paths as features.
`bundle.json` enumerates all files and available views; checksums.sha256 covers every
payload and manifest except itself. Do not include a file's own digest inside itself.

Paths are relative to DATA_ROOT, POSIX, case-stable and free of `..`, absolute paths,
external symlinks, usernames or host-specific roots. A future preflight verifies
checksums, row counts/schema, roles, membership disjointness and reference closure;
unknown files/columns/scopes cannot silently become inputs. Scalers/vocab/cache keys
include fold, fitting membership, model/normalizer and builder revisions.

**Upload later:** the prepared `data/phase2/` directory, or a builder-exported subset
with the same root manifest layout containing one fold and its required view closure.
Do not manually copy a leaf `train/` directory without its validation/metadata and
manifests. Set DATA_ROOT to `/content/phase2` (Colab) or `/workspace/phase2` (RunPod).
The bundle is data-self-contained; notebooks additionally need a pinned install of
SeqLogAD Python modules and licensed/pinned model assets, not the raw-data tree.

Future evaluation-only data belongs in separate `data/phase2-evaluation/` (also NOT
CREATED YET), never beneath the training upload root. Synthetic case truth and any
future authorized source labels remain evaluator-only. Real label export is blocked
by C2. P3 target burn-in is a separately authorized bundle; P4 target evaluation and
its labels stay outside P2 packaging and cannot be used for model selection.

## 9. Minimum common evidence envelope

Each prediction declares schema/expert/role/fold/architecture/unit IDs, record IDs,
raw score and direction (higher = more anomalous), uncertainty and its method,
coverage, evidence/localisation coordinates, status/reason, model revision,
checkpoint/input-manifest/context-config hashes. Define output granularity and
mapping from event/window/graph to evaluation units; missing events use gap/context
coordinates rather than invented observed record IDs.

`score_calibrated = null`, `calibration_status = NOT_CALIBRATED` in P2.
Unknown uncertainty is null with a reason, never fabricated zero. Coverage is a
measurement with denominator, not probability of correctness. Unsupported/absent
input yields LOW_COVERAGE or ABSTAIN; never silently fill missing scores with zero.
Evidence is model attribution/context, not proof of causality. P2.5 must implement
strict validation and positive/negative examples; P2.0 tests guard declarations only.

## 10. Evaluation, failure criteria and non-frozen decisions

Compare reference vs lightweight on identical source memberships, context access,
controls and scoring units. Report differing representation dependencies honestly.
Include semantic-only, sequence-only and GTAT-only diagnostics; measure residual
sequence cases after semantic/graph signals. No adaptive gate implementation in P2.
Preserve P3.6's Transformer/Isolation Forest/equal-weight baseline obligations;
cheap rarity/count/Markov comparators are comparisons, not a restored old roadmap.

Preregister candidate configurations, trainable parameters, token/window budgets,
seeds, stopping rules, source selection metric, uncertainty/resampling unit and
practical margin. AP, FAR and double-fault require legal real labels: blocked by C2.
Label-free disagreement is not double-fault or proof of useful complementarity.
Synthetic contrasts provide mechanism diagnostics, not population performance.
No fixed 0.01 AP margin is inherited from EFFECT-001. No winner may be chosen from
outer target labels or after repeatedly looking at final evaluation.

Failure criteria: input/reference hash mismatch; forbidden partition/label access;
loss of order/multiplicity/session boundaries; unbounded context claim; graph
coverage misrepresented; missing evidence/version; nonreproducible notebook/run;
lightweight candidate absent; unapproved source-label metrics; winner declared
without sufficient evidence; unresolved material conflicts. Fail closed and report
unsupported cases; do not reopen P1 or substitute fake metrics to pass a gate.

**Frozen:** responsibilities/IDs, Sequence-LoRA reference status, required lighter
candidate, GTAT non-substitutability until tested, P1 leakage restrictions, source-only
P2 boundary, portable root/manifest convention, notebook deliverables, no P3 activation.

**Open:** P2.PRE concrete base/tokenizer metadata; C2 source-evaluation label scope; exact semantic loss,
LoRA rank/targets/revisions; lightweight family and numeric resource criterion;
GTAT full specification; context/window/end policy; normal-reference assumptions;
source selection metrics/margins; physical view/evidence schema implementation;
sequence winner. Retain reference checkpoints/evidence and all candidate dispositions
even if a later approved comparison chooses the lighter model. Freeze each before
dependent implementation/training, with
researcher authority where scientific selection/data access is affected.
