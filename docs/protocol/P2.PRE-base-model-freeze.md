## C. Frozen project decisions

**Base and adapters.** Semantic and Sequence reference share the same immutable
upstream base and quantizer configuration. Adapter weights, optimizer state,
resume lineage and checkpoints are independent. A quantized runtime representation
is not byte-identical to BF16 source weights. Only one adapter is active per forward;
no shared activations or free second inference are assumed.

**Tokenizer.** Load `AutoTokenizer` from the pinned repo/commit with `use_fast=True`,
`trust_remote_code=False`. Use existing EOS as padding without extending vocabulary;
right-pad training, left-pad generation. Mask padding by attention-mask positions,
not every EOS token ID. Disable automatic special-token insertion; add one existing
BOS per independent context and EOS only at a genuine completed unit boundary.
Never invent EOS at a truncation boundary. No chat template or EventID-specific
tokens. Vocabulary/embedding mutation requires a separately justified amendment.
Literal special-token text must not silently become control tokens.

**Context.** Upstream capability is 128K. SeqLogAD practical cap is 2,048 tokens
including specials; low-memory cap 1,024; preflight begins at 512. Actual semantic
and sequence horizons remain P2.1/P2.2 decisions. No silent tokenizer truncation:
construct bounded units/windows, record dropped spans and coverage, preserve order,
sessions and partition boundaries. A larger cap requires a versioned amendment.

**Precision.** Prefer native BF16, checked with
`torch.cuda.is_bf16_supported(including_emulation=False)`.
FP16 is conditional on a successful finite-loss/gradient preflight with GradScaler
and FP32 trainable adapter parameters. On overflow/NaN/Inf, stop and use suitable
BF16 hardware; do not silently alter the experiment. FP32 remains for sensitive
operations/master parameters as specified by k-bit preparation; no full-FP32
training fallback. PyTorch warns that BF16-pretrained models can overflow FP16.
[Pinned CUDA implementation](https://raw.githubusercontent.com/pytorch/pytorch/v2.9.1/torch/cuda/__init__.py),
[AMP documentation](https://docs.pytorch.org/docs/2.9/amp.html).

**Training modes.** Default `QLORA_NF4_DOUBLE_QUANT`; low-memory
`QLORA_NF4_DOUBLE_QUANT_LOW_MEMORY`. Both use 4-bit NF4, nested quantization,
uint8 storage, resolved BF16/conditional FP16 compute, gradient checkpointing and
disabled training KV cache. The low-memory profile uses micro-batch 1 and <=1,024
tokens. Record effective batch, accumulation and context differences; do not pool
mode/precision results silently. Standard 16-bit LoRA or 8-bit loading is not an
automatic fallback. No adapter/trainer is implemented here.

**PEFT.** Use Hugging Face PEFT additive low-rank adapters, `bias=none`, immutable
base and embeddings, no saved/trainable base modules. Explicit target-module
allowlists are finalized before owning-task runs. Canonical checkpoints remain
unmerged `adapter_model.safetensors` plus `adapter_config.json`; never overwrite
the base. [Official checkpoint format](https://huggingface.co/docs/peft/developer_guides/checkpoint).

**Runtime.** Python `>=3.12,<3.13`, Linux x86_64, PyTorch CUDA 12.8 (`cu128`), one
GPU, SDPA. Fixed direct versions already verified from PyPI metadata:
torch 2.9.1, transformers 4.57.6, peft 0.18.1, accelerate 1.12.0,
bitsandbytes 0.49.2, tokenizers 0.22.2, safetensors 0.7.0,
huggingface-hub 0.36.2. Each official version URL and requirements are in the
verification record. This deliberately retains a compatible Transformers 4.x
baseline after inspecting newer releases; it does not claim to be the latest stack.
Selected direct constraints/Python markers agree; full transitive resolution,
imports and GPU kernels remain P2.1 preflight. Existing macOS `requirements.lock`
is not a Linux CUDA lock. Resolve/save a full Linux lock and install report before
training; incompatible Colab preinstalls require a matching environment, not silent
upgrades. No datasets/TRL/flash-attn/DeepSpeed/vision/audio dependency is added.
[Official PyTorch wheel matrix](https://pytorch.org/get-started/previous-versions/),
[bitsandbytes 0.49.2 requirements](https://huggingface.co/docs/bitsandbytes/v0.49.2/installation).

**Compute envelope.** Preferred candidate: native-BF16 Ampere-or-newer GPU with
24 GB VRAM; 48 GB offers headroom. A 16 GB T4-class device is a conditional
low-memory candidate, not a measured minimum or fit guarantee. All are project
planning estimates. Weight-only arithmetic (~16.06 GB BF16 or ideal ~4.02 GB at
4 bits) excludes activations, unquantized layers, logits, optimizer and overhead.
No SeqLogAD VRAM, training-time or throughput measurement exists.

**Artifacts.** Preserve `OUTPUT_ROOT=outputs/phase2` and
`<fold_id>/<expert_id>/<run_id>/`. Save config, training/allowed validation metrics,
logs, manifest, environment, dependency lock/install report, checksums and separate
checkpoints. Record base/tokenizer revisions, seed, data manifest hash, code commit
and dirty diff, timestamp/hardware, mode/precision/quantizer, adapter config and
resume/RNG/optimizer lineage. Model cache stays external. No real run directory is
created; `planned_artifact` remains a future metadata-only freeze receipt.

**Colab-first notebook/data contract.** Every future Phase-2 task performing real
training must supply a Colab-ready `.ipynb`; RunPod is secondary. Python modules
remain authoritative. P2.PRE does not create a training notebook.
