# Reproducibility Baseline

Day 1 established the initial conventions. Research Freeze v1.1 adds explicit dataset-suitability tests, sequence-destruction controls, conditional complexity gates, five-way split ownership, and a physical TEST-seal requirement. EFFECT-001 is human-approved with `delta_HDFS = delta_BGL = 0.01 AP`; most scientific runtime automation remains planned.

## Python environment contract

- Python policy: `>=3.12,<3.13`; ENV-001 was verified with Python 3.12.6.
- `pyproject.toml` is the single dependency contract and package metadata source.
- The isolated editable-build backend is pinned to setuptools 80.9.0 in `pyproject.toml`.
- `requirements.lock` is a tested resolution snapshot, used as constraints rather than a second independently edited dependency declaration.
- The canonical package namespace is `seqlogad.*` under `src/seqlogad/`.
- `.venv/` is project-local and ignored by Git; global site-packages are not part of a reproducible run.
- Editable installation and imports must work without `PYTHONPATH`, `sys.path` edits, or repository-root cwd assumptions.

Recreate the tested development environment with:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -c requirements.lock -e ".[dev]"
python -m pip check
python -m pytest -q
```

The lock snapshot records the versions tested on macOS ARM64. A future platform-specific re-resolution must remain within `pyproject.toml` bounds, pass the same checks, and update the snapshot intentionally with its platform noted.

## Experiment identity

Experiment IDs use the form:

```text
EXP-YYYYMMDD-NNN
```

`NNN` is a zero-padded sequence allocated for that date. A planned experiment must not be confused with a completed experiment.

## Required run metadata

Every future run records:

- `experiment_id`;
- timestamp;
- Git revision, when the repository is under Git;
- Git dirty state;
- config path and config snapshot;
- random seed;
- dataset identifier, version and checksum;
- parser version/config;
- canonical event/template schema version and schema artifact hash;
- sequence/mutation schema versions, split-manifest ID, partition-assignment ID, ordered-event content hash, and schema artifact hash;
- sequence strategy;
- model name/version/config;
- baseline/sequential method and negative-control artifact IDs;
- conditional gate decision IDs, when applicable;
- threshold strategy;
- metrics;
- output paths;
- hardware metadata;
- package lock/version information;
- failure status and notes.

## Seed convention

- The default seed is `42` unless an experiment explicitly overrides it.
- Seed `42` is a reproducibility default, not a scientifically meaningful value.
- Every model/run logs its seed.
- Multi-seed studies are explicit experiment groups.
- A seed is never changed silently after inspecting results.

## Output convention

The canonical run directory is:

```text
outputs/runs/<experiment_id>/
├── config/
├── logs/
├── metrics/
├── artifacts/
└── reports/
```

Large or typed artifacts may additionally be stored under the existing category directories using the same experiment ID:

```text
outputs/checkpoints/<experiment_id>/
outputs/indexes/<experiment_id>/
outputs/results/<experiment_id>/
outputs/reports/<experiment_id>/
outputs/traces/<experiment_id>/
```

Do not write `output.csv`, `result-final-v2.csv` or `latest-model.pt` at repository root. Existing runs must not be overwritten.

## Data and transformation rules

1. Raw benchmark data is immutable after acquisition.
2. Dataset version/checksum is recorded before processing.
3. Parser and transformation fit scope is recorded.
4. Thresholds and any conditional method weights are not tuned on the final TEST set.
5. Metrics should be generated by evaluation scripts rather than entered manually.
6. Test and validation leakage checks are required before research claims.
7. Any future downstream evidence/tool calls require separate traceable artifacts and cannot change detector results.
8. Real anomaly labels may filter authorized normal pools and support validation/evaluation; they never enter model inputs or base self-supervised losses.
9. Synthetic mutation labels are generated only from training-derived normal sequences.
10. The final TEST partition remains inaccessible to fitting, threshold tuning, model/dataset/architecture/claim selection, calibration, and checkpoint selection.

## Frozen split and gated-experiment convention

`PROTOCOL-001` v1.1 freezes the chronological split as `BASE_TRAIN` 60%, reserved `FUSION_TRAIN` 10%, `VAL_EXPERT` 10%, reserved `VAL_FUSION` 10%, and `TEST` 10%. HDFS block/session atomicity may cause recorded realized ratios to differ after boundary purging. BGL windows are created only after partitioning and never overlap. Sources of truth are [`research-protocol-v1.1.md`](research-protocol-v1.1.md) and [`../configs/protocols/protocol-v1.1.yaml`](../configs/protocols/protocol-v1.1.yaml).

SCHEMA-COMPAT-001 requires every current split/sequence identity to be created through `build_active_partition_identity(...)`, which pins Protocol `1.1` and derives the frozen target ratio. Explicit historical `1.0` identities remain readable, but a missing, unsupported, or implicitly defaulted protocol version is invalid. KT-3 uses the separate `SequenceDestructionRecord`; it never reuses synthetic-localization mutation semantics.

Default execution stages:

1. Use the frozen EFFECT-001 contract with `delta_HDFS = delta_BGL = 0.01 AP`; never alter it after observing outcomes.
2. Freeze raw split identities and physical TEST guard before parser/window generation.
3. Fit/freeze parser on normal `BASE_TRAIN`; create canonical events/sequences inside partitions.
4. Human runs KT-1/KT-2 order-insensitive suitability analyses.
5. Human runs Markov/N-gram and KT-3 sequence destruction.
6. Human records kill/gate decisions before any conditional method.
7. Freeze selected artifacts/claims; human executes final TEST once.

Transformer, localization, and fusion are conditional rather than default stages.

## EFFECT-001 statistical reproducibility

Every future primary comparison snapshots both `configs/protocols/protocol-v1.1.yaml` and `configs/protocols/effect-001.yaml`. The latter freezes non-interpolated Average Precision, one contrast per dataset, the required orderless family, validation-only selection, a 12-config family-level budget, three stochastic seeds, a 95% paired cluster-percentile bootstrap with 10,000 valid replicates and resampling seed `42`, explicit degenerate-resample handling, and the four scientific decision regions.

HDFS resampling units are complete block/sessions; BGL units are complete non-overlapping 100-event parent windows. All methods in a contrast reuse identical resampled unit IDs. Seed variability is reported separately from evaluation-unit bootstrap uncertainty. The final interval is conditional on the validation-selected methods and does not estimate model-selection uncertainty.

`delta_HDFS` and `delta_BGL` are both frozen at `0.01 AP` under `RESOURCE_FEASIBILITY_MARGIN`. Approval is recorded as human-owned, pre-experiment, and not result-informed. The values cannot be revised from TEST, KT outcomes, interval width, or whichever value helps the sequential method. Old contract snapshots are never overwritten in run artifacts.

## Human/AI ownership

AI/Codex may prepare implementation, configs, tests, commands, and evaluation scripts. The human researcher owns practical-effect thresholds, empirical execution/training/tuning, validation-only selection, final TEST execution, and conclusions. Planned experiment rows remain `NOT_RUN`; no metric may be fabricated or manually promoted to a run result.

## Dataset reproducibility

- Raw source files are immutable after verification and are never committed to Git.
- Each dataset has a version-controlled acquisition contract recording source, expected files, usage status and raw/manifest paths.
- A real dataset is experiment-ready only when required files are present and a schema-versioned manifest verifies successfully.
- Every raw file receives a streaming SHA-256 digest. Source-published MD5 may verify an archive transfer but never defines scientific dataset identity.
- The dataset fingerprint is SHA-256 over sorted repository-relative `path:file_sha256` entries; file discovery order and modification time do not affect it.
- Acquisition instructions and the source reference are retained even when automated download is unavailable.
- Manifest verification is non-mutating. A mismatch creates a failure report, not a repaired or overwritten manifest.
- Experiments must record the dataset ID, source snapshot/version and verified fingerprint. `schema_version` and `dataset_version` are separate concepts.
- HDFS/BGL provenance fields that cannot be observed before acquisition remain null or explicitly `UNVERIFIED`; they are not inferred.

## Repository revision tracking

The project is now a Git repository. Future experiment records must capture the commit and dirty state; a dirty worktree must never be represented as a clean revision.
