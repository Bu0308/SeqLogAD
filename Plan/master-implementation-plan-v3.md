**Status:** ACTIVE PLANNING CONTRACT

**Date:** 2026-08-14

**Empirical status:** NO MODEL EXPERIMENTS RUN

**Novelty status:** UNVERIFIED / PRIOR-ART VALIDATION REQUIRED

## 1. Official direction

> **Multi-Model Sequence Anomaly Localization with Structured Evidence Fusion and Evidence-Grounded Regression-Test Recommendation**

Central question:

> Do heterogeneous log-anomaly experts provide measurably complementary evidence, and can a scientifically justified fusion mechanism exploit that complementarity without double-counting redundant evidence or becoming less reliable under expert disagreement?

SeqLogAD remains a sequence-aware AI investigation and QA layer above observability infrastructure. It is not an ELK/Elasticsearch/Kibana replacement, generic chatbot, or generic multi-agent system.

## 3. Scientific terminology

Preferred description:

> **Normal-only self-supervised sequential anomaly detection with synthetic supervision for localization and fusion.**

Real HDFS/BGL anomaly labels are evaluation-only unless a separately approved experiment states otherwise. Synthetic targets are generated only from training-derived normal sequences. TEST labels are reserved for locked final evaluation.

## 4. Architecture

```text
Raw logs
→ integrity/provenance
→ canonical events
→ frozen train-fitted Drain3/templates
→ dataset-specific sequences
→ leakage-safe five-way partitions
→ independent experts A–D
→ frozen ExpertEvidence
→ calibration
→ complementarity/retention gate
→ F0–F7 fusion baselines
→ F8 structured evidence fusion
→ anomaly + coordinate-aware localization + reliability
→ downstream evidence-grounded investigation
→ regression-test recommendation
```

The LLM/agent is a downstream read-only consumer of frozen evidence. It cannot train, modify, or override the detector/fusion pipeline.

## 5. Data contracts

### Five-way candidate protocol

| Partition | Purpose |
|---|---|
| `BASE_TRAIN` | Fit parser, vocabularies, base experts, normal-reference corpus |
| `FUSION_TRAIN` | Generate training-derived synthetic cases and fit fusion |
| `VAL_EXPERT` | Expert hyperparameters/checkpoints and optional calibrator comparison |
| `VAL_FUSION` | Fusion/calibration/threshold/abstention selection |
| `TEST` | Locked final evaluation only |

Exact percentages are **TO BE FINALIZED** before preprocessing and may not be chosen after seeing model results.

### Grouping

- HDFS: keep all events for a block/session in one partition; assign chronology using an approved group timestamp rule.
- BGL: split the raw timeline first, then create windows wholly inside partitions.
- Parser state is fitted on the authorized earliest training scope and frozen before later partitions are transformed.

### Localization

- Token positions: extra, replacement, repeated observed events.
- Gap positions: missing events; `E1 E2 E3` has `G0 E1 G1 E2 G2 E3 G3`.
- Transition positions: unexpected transitions and reorder-related evidence.

MutationRecord must preserve source sequence, seed, operation, parameters, expected/observed sequences, affected coordinates, and artifact identity.

## 6. Heterogeneous experts

### Expert A — SeqLogAD-T

Lightweight causal Transformer for long-range sequence context/order and coordinate-aware localization. Candidate outputs are next-event probabilities/energy, sequence score, and optional token/gap/transition scores.

Candidate loss stages:

- A0: next-event objective.
- A1: A0 plus normal-vs-mutated ranking.
- A2: A0 plus masked token/gap/transition localization.
- A3: A0 plus ranking plus localization.

The loss combination is not claimed novel.

### Expert B — Markov/N-gram

Fit smoothed event-transition counts only. Produce short-range transition surprise such as negative log conditional probability, with explicit transition evidence.

### Expert C — Isolation Forest

Fit quantitative features such as sequence length, event frequency, unique-template ratio, repetition, transition rarity, entropy, and optional validated timing features. It does not emit token locations unless a positional feature explanation supports them.

### Expert D — Normal-reference retriever

Compare an observed sequence to `BASE_TRAIN` normal references. P0 uses edit distance, LCS, event n-gram overlap, and transition overlap. Output nearest IDs, similarity/distance, and expected-vs-observed structural differences. Dense retrieval is P1.

## 7. ExpertEvidence contract

Every expert output must include:

- dataset/sequence/partition identity;
- expert/model/checkpoint/config identity;
- raw and optional calibrated sequence scores;
- supported token/gap/transition scores;
- structured support/contradiction claims;
- evidence references and nearest-normal IDs where applicable;
- uncertainty and latency;
- fit-scope provenance.

Unsupported fields remain absent. Scores are not silently treated as calibrated probabilities.

## 8. Complementarity gate

Fusion is scientifically blocked until frozen out-of-sample evidence supports analysis of:

- score correlation;
- prediction disagreement;
- error overlap/double fault;
- oracle ensemble gain;
- anomaly-family conditional performance;
- token/gap/transition localization overlap;
- leave-one-expert-out marginal contribution.

An expert with no meaningful incremental value is removed or demoted. The project does not preserve four experts merely for architectural symmetry.

## 9. Fusion ladder

| ID | Comparator |
|---|---|
| F0 | Strongest individual expert |
| F1 | Normalized mean |
| F2 | Validation-weighted average |
| F3 | Voting/rank voting |
| F4 | Logistic stacking |
| F5 | MLP stacking |
| F6 | Standard gating/MoE |
| F7 | Evidential/Dempster-Shafer baseline if technically applicable |
| F8 | Structured Evidence Consensus Fusion candidate |

F8 may use calibrated scores, coordinate-aware localization, structured claims, evidence family, expert reliability, dependency/redundancy estimates, and disagreement/conflict indicators.

Minimal candidate fusion objective:

```text
L_F = L_detection + lambda_location * L_fused_localization
```

Potential redundancy objective:

```text
L_red = sum over i<j of R_ij * alpha_i * alpha_j
```

`L_red` is blocked until prior-art and measurable-need gates pass. Calibration is infrastructure, not novelty. Conflict is an input, verifier signal, abstention signal, and evaluation variable. The collapse-prone `confidence × conflict` objective is excluded.

## 10. Research questions and falsification

| RQ | Hypothesis under test | Falsification condition |
|---|---|---|
| RQ1 Expert value | Experts capture different mechanisms | No family-specific value or simple baseline dominance |
| RQ2 Complementarity | Errors/localizations are measurably complementary | Near-complete overlap and negligible oracle gain |
| RQ3 Fusion | F8 beats strongest single and appropriate F1–F7 | No reliable paired improvement |
| RQ4 Reliability | Dependency handling improves calibrated/FPR control | Detection loss or no reliability gain at matched coverage |
| RQ5 Downstream | Structured evidence improves grounding/test utility | No grounding or human-acceptance improvement |

All remain **HYPOTHESIS — TO BE TESTED**.

## 13. Default training stages

1. Freeze raw identity, parser, sequences, partitions, and mutation contract.
2. Human fits/trains experts independently.
3. Freeze expert checkpoints.
4. Human generates fusion-development ExpertEvidence.
5. Calibrate without TEST.
6. Measure complementarity and decide expert retention.
7. Human trains F0–F8 fusion conditions.
8. Human selects validation thresholds/optional abstention.
9. Human executes locked TEST.

End-to-end joint training is not default. Partial unfreezing is P1 and requires a registered experiment.

## 14. Evaluation matrix

Detection reports Precision, Recall, F1, PR-AUC, FPR, latency, throughput, and memory. Localization reports token/gap/transition metrics separately. Calibration reports ECE, Brier, NLL, and reliability curves. Complementarity reports pairwise and oracle/marginal metrics. Fusion reports the same metrics plus overhead and risk-coverage where abstention is enabled.

Use fixed seeds, paired bootstrap confidence intervals, and appropriate paired statistical tests. Negative and failed runs are retained.

## 15. Implementation phases

### Phase 0 — Governance and environment

Complete LIT-001, approve V3 ADRs, resolve package/import and PyArrow/Drain3 environment contracts, and freeze config/run metadata rules.

### Phase 1 — Canonical data

Implement schemas, parser lifecycle, HDFS/BGL adapters, sequence builders, five-way split, leakage audit, and deterministic coordinate-aware mutations.

### Phase 2 — Experts

Implement baseline score contract, Markov/N-gram, Isolation Forest, LSTM baseline, SeqLogAD-T A0–A3, structural Expert D, and ExpertEvidence serialization. Human performs training/fitting.

### Phase 3 — Complementarity and fusion

Implement calibration, complementarity metrics, F0–F7, structured claim alignment, F8, optional gated redundancy, and conflict-aware abstention evaluation. Human decides retention and runs fusion.

### Phase 4 — Evaluation

Generate paired RQ1–RQ4 reports, freeze decisions, and let the human execute final TEST.

### Phase 5 — Downstream

Use frozen evidence for verifier/investigation/test recommendation RQ5. Add API/UI/Elasticsearch only after scientific artifacts are stable.

## 17. Critical gates

### Implementation gate

Research implementation begins only after V3 human review, LIT-001 framing, environment contract, and schema/split decisions are approved.

### Fusion gate

F8 training begins only after experts produce frozen evidence and COMP-001/COMP-002 justify the retained set.

### Final-test gate

TEST begins only after configs, checkpoints, fusion, thresholds, hypotheses, and analysis scripts are frozen. Human executes and records the command.

### Downstream gate

Agent/test-recommendation evaluation begins only from versioned frozen evidence artifacts. It never substitutes for detector evaluation.
